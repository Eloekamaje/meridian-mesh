# Pilote local — 2026-11-01

Périmètre : installation reproductible du plugin et mesure des deux workflows pilotes
(`incident-paiements`, `changement-reglementaire`) avec la CLI Claude Code.

## Installation

```bash
scripts/install-meridian-plugin.sh --check
```

Résultat : manifeste `meridian.plugin/1` valide (4 skills, 3 agents, 2 domain packs,
policy, contrat, MCP), et liens `.claude/skills/meridian-*` présents. Le script imprime
la commande `claude mcp add meridian --scope project ...` sans toucher à `~/.claude`.

## Dry-run

Depuis `backend/` :

```bash
PYTHONPATH=..:../backend .venv/bin/python ../plugin/meridian/evals/run_benchmark.py \
  --scenario ../plugin/meridian/evals/scenarios/incident-paiements.json \
  --scenario ../plugin/meridian/evals/scenarios/changement-reglementaire.json \
  --runs 1 --max-budget-usd 1.00 --tenant demo --dry-run
```

Sortie : `/tmp/meridian-dryrun-all-20261101.txt` (exit `0`, 6 commandes = 3 bras × 2
scénarios). Vérifications faites :

- MCP généré : `backend/.venv/bin/python -m plugin.meridian.mcp.server`,
  `PYTHONPATH` racine, tenant `demo`, persona `architecte` ;
- `skill+mcp` : `Skill,Read` + tools MCP du scénario, cwd racine du dépôt ;
- `checklist+mcp` : même MCP, checklist générique, cwd vide ;
- `data-only` : pack JSON chargé (aucune erreur), sans MCP ni `--strict-mcp-config` ;
- skills visibles : `incident-ops`, `architecture-impact`, `benefits-okr`,
  `enterprise-portfolio`.

## Smoke test MCP

Le serveur a été lancé via le protocole MCP stdio avec la configuration générée :
initialisation `meridian 0.1.0`, **15 tools** listés, appel `meridian_impact` sur
`conduit` réussi (lecture seule). Cela valide le couple commande/env du MCP ; le
run Claude réel reste bloqué par le crédit API.

## Run réel

Commande (un seul bras pour rester sous 1,00 USD par scénario) :

```bash
cd backend
PYTHONPATH=..:../backend .venv/bin/python ../plugin/meridian/evals/run_benchmark.py \
  --scenario ../plugin/meridian/evals/scenarios/incident-paiements.json \
  --scenario ../plugin/meridian/evals/scenarios/changement-reglementaire.json \
  --runs 1 --max-budget-usd 1.00 --tenant demo --arm skill+mcp \
  --output /tmp/meridian-pilot-20261101
```

Résultat : **0/2**, coût **0,00 USD**, durée rapportée **2,55 s**. Les deux runs se
terminent sur `Credit balance is too low` (returncode 1), sans tour modèle facturé
ni appel d'outil MCP. Ce n'est pas un échec des workflows : le budget disponible
côté CLI/API est insuffisant.

Artefacts : `/tmp/meridian-pilot-20261101/`.

## Limites

- Aucune exécution réelle exploitable : authentification `claude` présente, mais crédit
  API épuisé. Ne pas interpréter 0/2 comme un résultat qualité.
- Le backend local tenant `demo` ne contient que les 3 jumeaux réels
  (`conduit`, `gestion-des-articles`, `meridian`) et 1 situation ; les Twins
  `paiements`, `comptes`, `fraude`, `support` des scénarios ne sont plus dans l'état
  courant. Les packs `evals/data/*.json` restent des instantanés valides.
- `/boucle/analyser` refuse la combinaison `situation_id` + `twin_ids`
  (`surface situation : sélecteur(s) non applicable(s) : twin_id`) ; le prompt de
  scénario contient les deux, donc un run réel doit soit tolérer ce 400, soit être
  rejoué sur un état de données compatible.
- Aucune revue humaine, aucune baseline/outcome, aucune preuve de supériorité
  statistique. Ce pilote ne démontre pas la production readiness.
