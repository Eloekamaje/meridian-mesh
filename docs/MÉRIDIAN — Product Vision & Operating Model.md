# MÉRIDIAN — De la découverte à l’exploitation continue de l’entreprise

## 1. Vision

Méridian ne doit pas être réduit à un réseau de jumeaux applicatifs.

Les **jumeaux**, le **Mesh**, les **Claims**, les sources, les relations et l’Atlas constituent la **fondation cognitive** du système. Ils permettent à Méridian de construire progressivement une représentation fiable, vivante et vérifiable de l’entreprise.

Mais la finalité du produit est ailleurs :

> **Méridian transforme en continu ce qu’il découvre sur l’entreprise en compréhension, en opportunités, en investigations, en décisions et en améliorations mesurables.**

La promesse n’est donc pas seulement de « connaître le SI ».

Elle est de permettre à l’entreprise de mieux comprendre ce qui lui arrive, d’identifier ce qui mérite son attention, de mobiliser les bonnes expertises et d’améliorer continuellement son fonctionnement.

Le cycle central devient :

> **Découvrir → Maturer → Exprimer → Investiguer → Décider → Agir → Mesurer → Apprendre**

Ce cycle ne remplace pas le triptyque historique de Méridian :

> **DÉCOUVRIR · COMPRENDRE · DÉCIDER**

Il lui donne une mécanique opérationnelle.

---

## 2. Le changement de centre de gravité

Jusqu’ici, une grande partie de la conception de Méridian s’est concentrée sur le réseau :

- naissance des jumeaux ;
- découverte des applications ;
- relations entre systèmes ;
- domaines ;
- Claims ;
- confrontation des sources ;
- découverte organique ;
- cartographie du SI ;
- Atlas.

Cette fondation reste essentielle.

Mais le **Mesh ne doit pas devenir le produit visible**.

Pour les utilisateurs, la valeur réelle apparaît lorsque Méridian est capable de répondre à des questions comme :

- Qu’est-ce qui mérite mon attention aujourd’hui ?
- Qu’est-ce qui est en train d’émerger ?
- Qu’est-ce qui devient préoccupant ?
- Où existe-t-il une opportunité d’amélioration ?
- Pourquoi ce phénomène apparaît-il ?
- Qui ou quoi est affecté ?
- Quelles expertises devons-nous mobiliser ?
- Quelles options avons-nous ?
- Quelle décision semble la plus pertinente ?
- Est-ce que la décision prise a réellement amélioré la situation ?

Le Mesh devient alors ce qu’est un système nerveux pour un organisme : indispensable, mais rarement le sujet principal de l’expérience.

# 3. Méridian comme système d’exploitation cognitif de l’entreprise

Méridian peut être vu comme un **système d’exploitation cognitif**.

Il ne remplace pas les systèmes opérationnels de l’entreprise.

Il les observe, les relie, les comprend et exploite leur connaissance collective.

Il doit être capable de faire quatre choses en permanence :

### 3.1 Observer

Collecter les faits provenant des applications, données, documents, événements, processus, outils, interactions et systèmes de référence.

### 3.2 Comprendre

Relier les observations, produire des Claims, confronter les sources, identifier les dépendances et construire progressivement une compréhension.

### 3.3 Faire émerger

Identifier qu’un ensemble de faits dispersés commence à former quelque chose de significatif :

- une friction ;
- une dérive ;
- un risque ;
- une incohérence ;
- une opportunité ;
- un changement émergent ;
- une simplification possible ;
- une amélioration potentielle.

### 3.4 Exploiter

Transformer cette émergence en action :

- investigation ;
- analyse multidisciplinaire ;
- scénarios ;
- recommandation ;
- décision ;
- initiative ;
- suivi ;
- apprentissage.

# 4. Le cycle vivant de Méridian

## 4.1 Découvrir

La découverte est la première responsabilité de Méridian.

Elle concerne notamment :

- les applications ;
- les services ;
- les API ;
- les bases de données ;
- les messages ;
- les dépendances ;
- les règles métier ;
- les processus ;
- les équipes ;
- les documents ;
- les changements ;
- les incidents ;
- les usages ;
- les parcours clients ;
- les tâches employés ;
- les événements opérationnels.

À ce stade, Méridian ne cherche pas nécessairement à conclure.

Il observe.

Un fait isolé ne devient pas automatiquement une vérité ou une alerte.

---

## 4.2 Maturer

La maturation est une fonction fondamentale.

Méridian doit résister à la tentation de transformer chaque observation en conclusion.

Une connaissance peut passer par différents niveaux :

**Observation → Hypothèse → Claim → Claim renforcé → Connaissance mature**

La maturation peut s’appuyer sur :

- plusieurs sources indépendantes ;
- l’historique ;
- la fréquence ;
- la cohérence temporelle ;
- la validation croisée ;
- les contradictions ;
- la qualité des preuves ;
- l’expertise spécialisée ;
- la répétition du phénomène ;
- la confiance calculée.

Exemple :

Un temps de réponse plus élevé ne signifie rien à lui seul.

Mais si Méridian découvre simultanément :

- une augmentation de latence ;
- davantage de reprises manuelles ;
- une hausse de plaintes ;
- une nouvelle règle métier ;
- un changement récent dans un service ;
- une évolution du taux d’abandon ;

alors une compréhension plus riche peut commencer à émerger.

---

## 4.3 Exprimer

L’expression est le moment où Méridian considère qu’un phénomène a suffisamment de sens pour être présenté.

Méridian ne présente donc pas seulement des données.

Il **exprime une lecture du réel**.

Exemples :

> Une friction semble émerger dans le parcours de renouvellement hypothécaire.

> Plusieurs équipes effectuent une activité équivalente avec des outils différents.

> Cette application semble progressivement perdre sa fonction propre au profit de services déjà présents ailleurs.

> Les interventions manuelles augmentent après une modification récente du processus.

L’expression doit toujours distinguer :

- les faits ;
- les hypothèses ;
- les preuves ;
- les incertitudes ;
- le niveau de confiance.

---

## 4.4 Investiguer

Une expression suffisamment importante peut devenir une investigation.

L’objectif n’est pas seulement de confirmer qu’un phénomène existe.

L’investigation cherche à comprendre :

- ce qui se passe ;
- depuis quand ;
- pourquoi ;
- où ;
- qui est affecté ;
- quelles dépendances sont impliquées ;
- quelles hypothèses sont plausibles ;
- quelles hypothèses sont éliminées ;
- quelles conséquences existent ;
- quelles expertises sont nécessaires.

Une investigation peut évoluer progressivement.

Elle peut commencer par un problème technique et devenir une question métier.

Exemple :

**Latence applicative → reprises manuelles → délai opérationnel → impact employé → abandon client → perte commerciale**

---

## 4.5 Décider

Une investigation mature doit produire des options.

Méridian ne doit pas seulement expliquer le passé.

Il doit aider à évaluer les futurs possibles.

Une investigation peut produire plusieurs scénarios :

- ne rien changer ;
- corriger localement ;
- modifier le processus ;
- automatiser ;
- déplacer une responsabilité ;
- remplacer un composant ;
- consolider deux capacités ;
- retirer une application ;
- transformer un parcours ;
- revoir une règle métier.

Chaque scénario peut être évalué selon :

- valeur ;
- coût ;
- complexité ;
- risque ;
- dépendances ;
- délai ;
- impact client ;
- impact employé ;
- impact réglementaire ;
- réversibilité ;
- confiance de l’analyse.

---

## 4.6 Agir

Une décision peut devenir une initiative.

L’action n’est pas exécutée silencieusement par Méridian.

Elle reste gouvernée par l’humain.

Méridian peut cependant :

- préparer les étapes ;
- identifier les responsables ;
- proposer les dépendances ;
- créer un plan ;
- identifier les éléments à surveiller ;
- définir les critères de succès ;
- maintenir la traçabilité entre problème, décision et action.

---

## 4.7 Mesurer

La boucle ne doit pas s’arrêter après une recommandation.

Méridian doit observer les conséquences réelles.

Exemple :

Avant :

> La modification devrait réduire de 15 % le délai de traitement.

Après :

> Le délai a diminué de 11 %, mais les interventions manuelles ont augmenté dans une autre équipe.

Cette différence entre **impact attendu** et **impact observé** est essentielle.

---

## 4.8 Apprendre

Chaque décision devient une nouvelle source de connaissance.

Méridian apprend progressivement :

- quelles recommandations ont fonctionné ;
- quels problèmes réapparaissent ;
- quels changements provoquent souvent des effets secondaires ;
- quels systèmes sont fréquemment impliqués ensemble ;
- quelles dépendances sont sous-estimées ;
- quelles décisions déplacent un problème ;
- quelles transformations produisent réellement de la valeur.

Méridian développe ainsi une **mémoire de transformation de l’entreprise**.

# 5. Les objets vivants de Méridian

Le produit devrait être organisé autour d’objets qui possèdent leur propre cycle de vie.

## Signal

Un fait ou changement observé.

Exemples :

- augmentation de latence ;
- nouvelle dépendance ;
- hausse d’erreurs ;
- changement de règle ;
- hausse de reprises manuelles ;
- modification d’un parcours.

Un Signal n’est pas encore un problème.

---

## Situation candidate

Plusieurs signaux semblent appartenir au même phénomène.

La situation reste encore incertaine.

---

## Expression

Méridian est capable de formuler ce que le phénomène semble signifier.

Une Expression possède :

- une formulation ;
- des preuves ;
- des Claims ;
- un niveau de confiance ;
- les entités concernées ;
- les contradictions éventuelles.

---

## Opportunité

Un phénomène révèle une possibilité d’amélioration.

Une opportunité n’est pas nécessairement liée à un dysfonctionnement.

Exemples :

- automatisation ;
- simplification ;
- réduction de duplication ;
- consolidation ;
- meilleure expérience client ;
- réduction du travail manuel ;
- retrait d’une capacité devenue inutile ;
- rationalisation du SI.

---

## Risque

Un phénomène pourrait entraîner une dégradation ou une conséquence négative.

---

## Investigation

Un travail structuré visant à comprendre suffisamment une situation pour permettre une décision.

---

## Scénario

Une option d’action issue d’une investigation.

---

## Décision

Le choix humain retenu.

---

## Initiative

La traduction de la décision en action suivie.

---

## Résultat

Ce qui est réellement observé après l’action.

---

## Apprentissage

La connaissance généralisable issue de l’expérience.

---

# 6. L’Opportunité doit devenir un objet majeur

Un système centré uniquement sur les anomalies deviendrait un outil d’observabilité avancé.

Méridian doit également chercher ce qui **pourrait fonctionner mieux**.

Il doit être capable de dire :

> Rien n’est cassé, mais il existe probablement une meilleure manière de faire.

Exemples :

### Travail manuel inutile

> 31 % des demandes reçues par le centre de contact concernent une information déjà présente dans trois systèmes internes.

### Duplication organisationnelle

> Deux équipes exécutent une activité similaire avec des processus et outils différents.

### Rationalisation applicative

> Une application conserve un coût important alors que la majorité de ses capacités sont désormais présentes ailleurs.

### Friction employé

> Plusieurs employés contournent régulièrement une étape officielle du processus.

### Parcours client

> Les abandons se concentrent autour d’une étape qui impose plusieurs validations internes sans valeur visible pour le client.

Ces découvertes peuvent devenir de véritables portefeuilles d’opportunités.

# 7. Les experts spécialisés

Les experts doivent être considérés comme des **capacités cognitives spécialisées**, pas comme de simples personas conversationnels.

Chaque expertise devrait définir :

- son domaine de compétence ;
- les types de questions qu’elle peut traiter ;
- les sources qu’elle peut consulter ;
- les outils qu’elle possède ;
- ses méthodes de raisonnement ;
- ses critères de preuve ;
- ses règles de confiance ;
- ses limites ;
- ses interactions avec les autres expertises.

---

## 7.1 Experts TI

- sécurité ;

- cloud ;

- qualité ;

---

## 7.2 Experts métier

Spécifiques au domaine de l’entreprise.

## 7.3 Experts processus

Ils reconstruisent la manière réelle dont le travail circule.

Ils peuvent comparer :

- processus observé ;
- contournements ;
- tâches manuelles ;
- automatisations ;
- dépendances.

---

## 7.4 Experts employés

- interruptions ;
- tâches manuelles ;
- transferts entre équipes.

L’objectif n’est pas de surveiller individuellement les employés, mais de comprendre les mécanismes de travail et les effets des systèmes sur les équipes.

## 7.6 Experts stratégie et transformation

# 8. Orchestration dynamique des expertises

Les experts ne doivent pas tous être mobilisés sur chaque sujet.

Méridian doit déterminer progressivement quelles expertises sont nécessaires.

Exemple :

### Étape 1

Une dégradation de performance apparaît.

**Expert performance** mobilisé.

### Étape 2

Le phénomène se concentre après une nouvelle règle.

**Expert métier** ajouté.

### Étape 3

Des reprises manuelles apparaissent.

**Expert processus / employé** ajouté.

### Étape 4

Les abandons augmentent.

**Expert parcours client** ajouté.

### Étape 5

Une modification plus large est envisagée.

**Expert architecture + transformation + finance** ajoutés.

Une investigation devient donc un espace où les expertises se construisent progressivement autour du problème réel.

---

# 9. Flore : interface d’exploitation de Méridian

Flore ne doit pas être limitée à un assistant de recherche.

Elle devient l’interface conversationnelle permettant d’exploiter l’intelligence de Méridian.

Questions naturelles :

> Qu’est-ce qui mérite mon attention aujourd’hui ?

> Pourquoi cette opportunité est-elle apparue ?

> Quelles preuves avons-nous ?

> Qu’est-ce qui reste incertain ?

> Qui est affecté ?

> Quels experts ont participé à cette conclusion ?

> Lance une investigation.

> Trouve les hypothèses concurrentes.

> Compare trois scénarios.

> Quelle option minimise le risque client ?

> Qu’est-ce qui changerait si nous retirions TBT ?

> Notre décision du mois dernier a-t-elle réellement amélioré la situation ?

Flore devient alors :

> **la conversation avec l’entreprise vivante.**

---

# 10. Atlas : la géographie, pas le produit entier

Atlas reste fondamental.

Mais il doit être repositionné.

Atlas répond principalement à :

- où cela se produit ;
- quelles entités sont concernées ;
- quelles relations existent ;
- quel domaine est touché ;
- quelle propagation est possible ;
- quelle partie du système est en transformation.

Atlas devient la **géographie de Méridian**.

Il ne doit pas être l’unique interface d’exploitation.

Lorsqu’un utilisateur ouvre une opportunité, une investigation ou un risque, Atlas peut automatiquement montrer la zone concernée.

---

# 11. Une page d’accueil orientée exploitation

La page d’accueil pourrait devenir un espace intitulé simplement :

# Aujourd’hui

Exemple :

- 1 risque en progression

### Ce qui demande une décision

### Ce qui apprend

- 2 initiatives ont produit des résultats mesurables

Chaque élément doit avoir une action :

> **Pourquoi Méridian pense cela**

# 12. Un exemple complet

## Découverte

Méridian observe sur plusieurs semaines :

- augmentation légère des délais ;
- hausse de certaines erreurs ;
- reprises manuelles plus nombreuses ;
- commentaires clients ;
- nouvelle règle métier ;
- modification récente d’un service.

Pris séparément, aucun élément ne suffit.

---

## Maturation

Les Claims sont confrontés.

Les signaux convergent.

La confiance augmente.

Une corrélation temporelle apparaît.

---

## Expression

Méridian exprime :

> Une dégradation progressive semble apparaître dans le parcours de renouvellement hypothécaire. Elle ne semble pas provenir d’un seul système.

---

## Investigation

Experts mobilisés :

- performance ;
- architecture ;
- métier hypothécaire ;
- processus ;
- employé ;
- client.

L’investigation découvre une chaîne :

> nouvelle règle → appel supplémentaire → délai → reprise manuelle → attente → abandon client.

---

## Scénarios

### Scénario A

Optimiser seulement le service.

### Scénario B

Modifier la règle métier.

### Scénario C

Éliminer une validation en reconstruisant le processus.

---

## Décision

Le responsable choisit le scénario B.

---

## Mesure

Trois semaines plus tard :

- délai : -11 % ;
- erreurs : -7 % ;
- abandons : -5 % ;
- reprises manuelles : +4 %.

---

## Apprentissage

Méridian conclut :

> La modification a amélioré le parcours client, mais a déplacé une partie de la charge vers les opérations.

Une nouvelle opportunité peut alors naître :

> automatiser la validation manuelle restante.

La boucle recommence.

# 13. La mémoire de transformation

À long terme, l’un des actifs les plus précieux de Méridian devient sa mémoire.

Il peut progressivement répondre à des questions comme :

- avons-nous déjà vu une situation similaire ?
- qu’avions-nous décidé ?
- pourquoi ?
- quel résultat avions-nous obtenu ?
- quels effets secondaires sont apparus ?
- quelles équipes ont été touchées ?
- quelles recommandations ont échoué ?
- quelles dépendances avons-nous découvertes trop tard ?

Cette mémoire transforme l’expérience historique de l’entreprise en capital exploitable.

# 15. Ce qui différencie Méridian

Méridian ne doit pas être positionné comme :

- un Knowledge Graph ;
- un outil de monitoring ;
- un outil d’architecture ;
- un moteur de recherche documentaire ;
- un chatbot d’entreprise ;
- un outil de process mining ;
- un simple Digital Twin ;
- une plateforme multi-agents.

Il peut utiliser certains de ces mécanismes.

Mais sa différence est leur combinaison autour d’une boucle continue :

> **observer → comprendre → faire émerger → investiguer → décider → apprendre**

Sa valeur vient de sa capacité à relier des phénomènes qui appartiennent traditionnellement à des mondes séparés :

> technologie ↔ processus ↔ employés ↔ clients ↔ métier ↔ stratégie

# 16. Principes de conception à conserver

## Preuve avant affirmation

Toute conclusion importante doit être rattachée à des éléments vérifiables.

## Incertitude explicite

Méridian doit pouvoir dire :

> Je ne sais pas encore.

## Découverte avant classification

L’organisation humaine existante est une source de contexte, pas nécessairement la vérité absolue.

## Expertise avant opinion

Une expertise doit avoir des méthodes, des preuves et des responsabilités.

## Opportunité autant que problème

Méridian doit chercher ce qui peut être amélioré, pas uniquement ce qui est défaillant.

## Humain dans la décision

Méridian éclaire, propose et mesure.

Les décisions significatives restent gouvernées.

## Boucle fermée

Toute recommandation importante devrait pouvoir être reliée à un résultat observé.

# 17. Nouvelle formulation de la vision

Une formulation possible :

> **Méridian est un système d’intelligence vivante de l’entreprise. Il découvre continuellement son fonctionnement réel, fait mûrir la connaissance, révèle risques et opportunités, mobilise les expertises nécessaires, accompagne les décisions et apprend de leurs résultats.**

Version courte :

> **Méridian transforme la compréhension vivante de l’entreprise en amélioration continue.**

Version plus institutionnelle :

> **Un réseau d’intelligences et de jumeaux vivants qui découvre l’entreprise, comprend ses dynamiques et éclaire ses décisions.**

---

# 18. La promesse produit

La question à laquelle Méridian doit finir par répondre n’est pas :

> Que contient notre SI ?

Mais :

> **Que devons-nous comprendre, décider ou améliorer maintenant ?**

Et la mesure ultime de la valeur de Méridian ne sera pas la quantité de jumeaux créés, de Claims stockés ou de relations découvertes.

Elle sera sa capacité à produire continuellement :

- une meilleure compréhension ;
- de meilleures décisions ;
- moins de travail inutile ;
- moins de risques ;
- plus d’opportunités ;
- des transformations mieux maîtrisées ;
- une mémoire institutionnelle exploitable.

---

# Conclusion

Les jumeaux applicatifs vivants et le Mesh constituent la fondation de Méridian.

Mais cette fondation n’est qu’un commencement.

Le véritable produit apparaît lorsque Méridian exploite cette intelligence pour faire émerger ce qui compte, mobiliser les expertises appropriées, mener des investigations, construire des scénarios, accompagner les décisions et mesurer les résultats.

Méridian devient alors moins une carte du système qu’un **mécanisme permanent de compréhension et d’amélioration de l’entreprise**.

> **Découvrir ce qui existe.  
> Comprendre ce qui se transforme.  
> Décider ce qui doit changer.  
> Apprendre de ce qui s’est réellement passé.**
